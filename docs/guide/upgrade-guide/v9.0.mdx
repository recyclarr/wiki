:::warning

This page tracks deprecations and breaking changes planned for Version 9.0, which is currently in
development. The content here may change as features are added, modified, or removed during the
development cycle.

:::

## Docker: Persistent Server {/*#docker-server*/}

The Docker image now runs the Recyclarr server instead of a cron job. The server stays running,
syncs on a built-in schedule, and accepts commands from the CLI. See the [Docker guide][docker] for
the full setup.

### API Key Required {/*#docker-api-key*/}

The server requires an API key of at least 32 characters and does not start without one. The image
has no default key. Set `RECYCLARR_API_KEY` on the container:

```yml
services:
  recyclarr:
    image: ghcr.io/recyclarr/recyclarr:9
    environment:
      - TZ=America/Santiago
      - RECYCLARR_API_KEY=${RECYCLARR_API_KEY}  # <<< ADDED
```

See [API Key][docker-api-key] for how to create the key and store it in a `.env` file or a Compose
secret. CLI commands you run with `docker exec` use the same key automatically.

### Schedule Moved to `settings.yml` {/*#cron-schedule*/}

The `CRON_SCHEDULE` environment variable is no longer read. Remove it from your compose file and put
the same cron expression in [`server.schedule.cron`][schedule-cron] in `settings.yml`. If you did
not set `CRON_SCHEDULE`, you can skip this step: the new default also syncs once a day at midnight.

```yml
services:
  recyclarr:
    image: ghcr.io/recyclarr/recyclarr:9
    environment:
      - TZ=America/Santiago
      - CRON_SCHEDULE=0 4 * * *  # <<< REMOVED
```

```yml
# settings.yml
server:
  schedule:
    cron: 0 4 * * *
```

### Container Arguments No Longer Run the CLI {/*#docker-run-args*/}

Arguments after the image name no longer run Recyclarr commands. For example,
`docker compose run --rm recyclarr sync` does not sync anymore. Run commands in the running
container with `docker exec` instead:

```bash
docker exec recyclarr recyclarr sync
```

If an external scheduler ran Recyclarr this way, see [Using an External Scheduler][external].

### Removed Environment Variables {/*#docker-env-removed*/}

Remove these variables from your compose file. Recyclarr ignores them:

- `RECYCLARR_CREATE_CONFIG`: Create your configuration files in `/config` yourself.
- `RECYCLARR_LOG_LEVEL`: Use `--log` on CLI commands to show log output on the console.

### Add a Restart Policy {/*#docker-restart*/}

The container must keep running for scheduled syncs to happen. Add a restart policy so the server
starts again after a crash or a reboot:

```yml
services:
  recyclarr:
    restart: unless-stopped
```

To call the HTTP API from outside the container, you also need to publish port `7982`. See
[HTTP API][http-api].

## Default Files No Longer Created {/*#no-default-files*/}

Recyclarr no longer creates the `configs` and `includes` subdirectories or an empty `settings.yml`.
A missing directory or settings file is not an error: without `settings.yml`, Recyclarr uses default
settings. Create these yourself when you need them. Existing files and directories keep working as
before.

By default, the state and data directories are inside the configuration directory, so Recyclarr
still creates it when it is missing. To leave the configuration directory untouched, for example to
mount it read-only, move both directories out of it with the new [`RECYCLARR_STATE_DIR`][env-state]
variable and [`RECYCLARR_DATA_DIR`][env-data]. See
[File Structure][file-structure].

If your configuration directory still has `cache` or `repo` folders from an older version, start
Recyclarr once with it writable so its [migrations][migrations] can move or delete them. You can
also delete the folders yourself. Otherwise, startup fails on a read-only mount.

## Invalid Configuration Stops the Server {/*#invalid-config*/}

Previously, when a configuration file had errors, Recyclarr reported them and still synced the
instances in your other files. Now the server checks your configuration files when it starts, and an
error in any of them stops it from starting. Fix every error the server logs, then start it again.
See [Client and Server][client-server].

## Log Files and Console Format {/*#logs*/}

Log files moved from `logs/cli/` to `logs/server/` in the [data directory][env-data]. The CLI no
longer writes log files; the server writes them instead. Use `--log` on CLI commands to show log
output on the console.

When its output is not a terminal, as with `docker logs`, the server now writes one JSON object per
line instead of text. To keep text output, set [`server.logging.format`][logging-format] in
`settings.yml`:

```yml
# settings.yml
server:
  logging:
    format: text
```

## CLI: Server Executable Required {/*#server-executable*/}

The release archives now contain two executables: `recyclarr` and `recyclarr-server`. The CLI sends
its work to a server and starts `recyclarr-server` from its own directory when needed. If you copy
the `recyclarr` executable somewhere by hand, copy `recyclarr-server` to the same directory. See
[Client and Server][client-server].

## CLI: `sync --config` Removed {/*#sync-config-removed*/}

The `-c|--config` option of `recyclarr sync` has been removed. The server loads configuration only
from its [default locations][default-yaml]. Move any configuration files you passed with `--config`
into the `configs` directory.

```bash
recyclarr sync --config ../myconfig.yml # <<< REMOVED
```

## CLI: `config` Commands Removed {/*#config-commands-removed*/}

The `recyclarr config create`, `recyclarr config list local`, and `recyclarr config list templates`
commands have been removed. To start from a template, copy it from the
[Quick Setup Templates][templates] page into your configuration directory.

## CLI: `migrate` Removed {/*#migrate-removed*/}

The `recyclarr migrate` command has been removed. Migrations already ran automatically, and they now
run each time the server starts. Remove any calls to `recyclarr migrate` from your scripts. See
[Migration System][migrations].

## CLI: `state repair` Removed {/*#state-repair-removed*/}

The `recyclarr state repair` command and its `--adopt` flag have been removed. Sync is now
self-healing: when a configured resource matches an existing resource in the service by name but has
no state mapping, Recyclarr automatically adopts it and emits a warning:

```txt
Adopted Custom Format '3D' (b8cd450cbfa689c0259a01d9e29ba3d6) from service ID 66
```

Previously, this scenario required running `recyclarr state repair --adopt` to resolve the conflict.
Common situations where this occurred:

- Pointing Recyclarr at an existing Sonarr/Radarr instance with matching resources
- Relocating a service to a new URL (changing `base_url`)
- Database rebuilds or instance migrations

All of these are now handled automatically during sync.

The only scenario that still requires manual intervention is **ambiguous matches**: when 2+ service
resources share the same name (case-insensitive), Recyclarr cannot determine which one to adopt. The
error message instructs you to resolve the duplicates in the service directly.

### New Mental Model {/*#authoritative-sync*/}

If it's in your config, Recyclarr owns it. If you want to manually manage a resource, remove it from
your config. Recyclarr warns you when it adopts something that already existed, giving you a chance
to notice and adjust your config if needed.
