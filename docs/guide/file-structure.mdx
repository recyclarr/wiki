This page describes the directory structure used by Recyclarr. Recyclarr separates its files into
three root directories:

- A **configuration directory** for the files you write.
- A **state directory** for files Recyclarr writes that must persist.
- A **data directory** for ephemeral files that can be regenerated.

By default, the data directory is the configuration directory itself, and the state directory is its
`state` subdirectory. You can separate them using [environment variables][env-vars] for cleaner
backup workflows or a read-only configuration directory.

## Configuration Directory {/*#config-directory*/}

The configuration directory holds your YAML configuration and settings. Everything here should be
included in [backups][backups].

| Platform | Default Location                          |
| -------- | ----------------------------------------- |
| Windows  | `%APPDATA%\recyclarr`                     |
| Linux    | `~/.config/recyclarr`                     |
| MacOS    | `~/Library/Application Support/recyclarr` |
| Docker   | `/config`                                 |

Override with the [`RECYCLARR_CONFIG_DIR`][env-config] environment variable.

### Contents {/*#config-contents*/}

```txt
<config directory>/
├── recyclarr.yml
├── configs/
├── includes/
├── settings.yml
├── cli.yml
└── state/
```

- `settings.yml`: Optional [settings][settings] for the server. Without it, Recyclarr uses default
  settings.
- `cli.yml`: Optional [CLI settings][cli-settings].
- `state/`: The default [state directory](#state-directory).

Recyclarr does not create `settings.yml`, `configs/`, or `includes/`. Create them when you need
them; none of them has to exist.

## State Directory {/*#state-directory*/}

The state directory holds files that Recyclarr writes and needs to keep. Include it in
[backups][backups]. If you lose it, Recyclarr no longer knows which Sonarr and Radarr resources it
created and has to [adopt them again by name][state].

By default, this is the `state` directory inside the configuration directory. Override it with the
[`RECYCLARR_STATE_DIR`][env-state] environment variable.

### Contents {/*#state-contents*/}

```txt
<state directory>/
├── radarr/
├── sonarr/
└── server.db
```

- `radarr/`, `sonarr/`: [Sync state][state] for each instance.
- `server.db`: Sync job history kept by a [persistent server][persistent].

## Data Directory {/*#data-directory*/}

The data directory holds ephemeral files that Recyclarr can regenerate on its own. These do not need
to be backed up.

If [`RECYCLARR_DATA_DIR`][env-data] is not set, data files are stored in the configuration directory
(the default behavior from prior versions).

### Contents {/*#data-contents*/}

```txt
<data directory>/
├── resources/
└── logs/
    └── server/
```

## Default YAML Configuration Files {/*#default-yaml*/}

Configuration files may be located in multiple places, each documented in the sections that follow.
For all supported locations, the following behavior applies:

- All methods may be used together and all corresponding YAML files will be loaded.
- You don't have to use all locations; you can choose only the ones you want to use.
- If at least one configuration file is not found, it will result in an error.
- All YAML files must have the `yml` or `yaml` extension.

### File: `recyclarr.yml` {/*#recyclarr-yaml*/}

The default YAML configuration file is named `recyclarr.yml` and it is always located in the
configuration directory (listed above based on platform). Example (using docker path):

```txt
/config/recyclarr.yml
```

You can name it `recyclarr.yaml` instead, but not both. If both files exist, Recyclarr reports a
configuration error.

### Directory: `configs` {/*#config-directory-yaml*/}

You can place any number of configuration YAML files in a subdirectory named `configs` under the
configuration directory. The following requirements must be met:

- All files must have the `.yml` or `.yaml` extension in order to be recognized.
- Every YAML file placed here is loaded. This behavior is non-recursive; meaning if you place YAML
  files in subdirectories under `configs/`, they will not be loaded.
- The names of the files are unimportant and can be whatever you want.

:::caution

Include templates should *not* be placed here; use the [`includes`](#include-directory) directory
instead.

:::
